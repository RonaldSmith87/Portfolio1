**4. Using .gitignore and Why it's Important**  
Most repositories contain a .gitignore file.

- What is the purpose of this file?
  <br>
  .gitignore is needed for dynamic project files generated by your IDE, Secrets, or local config files not needed by the repo as a whole.

- What is the "**.DS_Store**" file and why would you want to ignore it?
  <br>
  .DS_Store or Desktop Services Store file should be ignored because its a meta data file automatically created that contains things like Icons for your folders and files. This will cause merge conflicts later because every user is unique and will generate their own ds_store file automatically. This is not a critical file for your project, ever.

- What other file or folder would you want to add to a .gitignore file and why?
  <br>
  You want to avoid adding files that contain secrets or credentials to your repo by adding these to th git ignore file. This should be obvious but the reason being security. next you want to add dependency or librarys that are external to your repo. These can be compiled into your final program and will just add bloat to your repo. Build outputs and binaries should be added as well because they will be offered as a release. Just because the build runs on your system does not mean it will run on everyone's. IDE files should be ignored, other devs will have their own that get populated for them. Cache and logs should be ignored because the cache will build it self and the log files can contain information you don't need to share. All these cause bloat to your repo as well.
